## 数据流架构

```
用户请求 → 格式检测 → 路由分发 → 凭证轮换 → API 调用
    ↓           ↓         ↓         ↓         ↓
响应处理 ← 格式转换 ← 结果解析 ← 错误处理 ← 网络请求
```

### 请求处理流程
1. **请求接收**：Web 框架接收 HTTP 请求
2. **身份验证**：验证 API 密钥和权限
3. **格式检测**：自动识别请求格式（OpenAI/Gemini）
4. **路由分发**：根据格式和端点类型路由到对应处理器
5. **凭证选择**：智能选择最优的可用凭证
6. **API 调用**：向 Google API 发送请求
7. **响应处理**：处理返回数据并进行格式转换
8. **结果返回**：返回用户友好的响应

### 并发处理架构
- **异步 I/O**：基于 asyncio 的高性能异步处理
- **请求池管理**：智能的 HTTP 连接池管理
- **负载均衡**：多凭证负载均衡和故障转移
- **流式处理**：真正的实时流式响应处理

## 存储架构

### 存储适配器设计

**文件位置**：`src/storage_adapter.py`, `src/storage/`

**支持的存储后端**：
- **文件存储**：本地文件系统存储（默认）
- **Redis 存储**：Redis 内存数据库，支持集群模式
- **MongoDB 存储**：MongoDB 文档数据库
- **PostgreSQL 存储**：PostgreSQL 关系型数据库

**存储管理器**：
- `file_storage_manager.py`：本地文件存储管理
- `redis_manager.py`：Redis 缓存和会话管理
- `mongodb_manager.py`：MongoDB 文档存储
- `postgres_manager.py`：PostgreSQL 关系数据存储
- `cache_manager.py`：多级缓存策略管理

### 数据持久化策略

1. **凭证数据**：支持多种存储后端，可配置存储方式
2. **使用统计**：TOML 格式文件存储，支持实时更新
3. **配置数据**：配置文件 + 环境变量，支持热更新
4. **会话数据**：内存 + Redis，支持分布式部署
5. **日志数据**：文件 + 可选的数据库存储

### 缓存策略

- **L1 缓存**：内存缓存，存储热点数据
- **L2 缓存**：Redis 缓存，支持分布式访问
- **L3 缓存**：数据库查询结果缓存
- **缓存失效**：基于 TTL 和事件驱动的缓存失效机制
